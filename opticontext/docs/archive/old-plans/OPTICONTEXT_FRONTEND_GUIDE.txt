================================================================================
PART 0 — GLOBAL DESIGN SYSTEM
================================================================================

The design language for OptiContext is called: Paper Precision.

The idea is simple. A warm, editorial surface — like technical paper — combined
with developer precision. Structured, serious, and exact. Nothing decorative that
doesn't earn its place.

This is not a startup template. This is infrastructure. The design should feel
like a well-made instrument, not a landing page generator output.

TYPOGRAPHY
------------------------------------------------------------------------

Display / Headlines:   Zodiak (serif)
  — Use for: H1, H2, hero statements, section titles
  — Weight: 400 (regular) for elegance, 600 (semibold) for emphasis
  — Never bold a Zodiak headline. It reads heavy.

Body / UI Text:        Switzer (sans-serif)
  — Use for: paragraphs, labels, nav, buttons, metadata
  — Weight: 400 for body, 500 for UI labels, 600 for button text

Code / Technical:      JetBrains Mono
  — Use for: all code blocks, API keys, endpoint strings, JSON, config snippets
  — Weight: 400 only
  — Never use another monospace font anywhere on the site

Type scale (base 16px):

  xs:    12px / 1.4  (Switzer — metadata, timestamps, labels)
  sm:    14px / 1.5  (Switzer — secondary body, captions)
  base:  16px / 1.6  (Switzer — primary body text)
  lg:    18px / 1.5  (Switzer — large body, intro paragraphs)
  xl:    22px / 1.4  (Zodiak — small section heads)
  2xl:   28px / 1.3  (Zodiak — subsection titles)

------------------------------------------------------------------------
MOTION SYSTEM
------------------------------------------------------------------------

All animation uses transform and opacity only.
Never animate layout properties (width, height, margin, padding).
Duration targets: micro 100ms, fast 150ms, standard 200ms, slow 300ms.
Easing default: cubic-bezier(0.4, 0, 0.2, 1) — standard ease.

Entrance animations:
  Fade + rise: opacity 0→1, translateY 8px→0, 200ms, standard ease
  Use for: page sections, modals, tooltips, cards on scroll

Hover states:
  Button lift: translateY -1px, shadow deepens, 150ms
  Card hover: translateY -2px, border strengthens, 200ms
  Never scale elements above 1.02 on hover

Interactive feedback:
  Button press: scale 0.97, 100ms
  Copy success: icon swap + color pulse, 1500ms total
  Form error: subtle horizontal shake, 300ms, only on submit

Scroll reveals:
  Sections fade + rise as they enter viewport
  Use IntersectionObserver with 0.15 threshold
  Stagger child elements by 60ms per item, max 5 items staggered
  Never stagger more than 5 elements in a row — it becomes noise

Page transitions:
  Fade out 150ms, fade in 200ms
  No sliding pages. No dramatic transitions.
  Auth → Dashboard: instant redirect, no transition animation

Avoid completely:
  Parallax of any kind
  Animated background blobs that move on scroll
  Bounce or spring physics
  Keyframe loops playing constantly
  CSS animations on background-position

------------------------------------------------------------------------
BACKGROUND SYSTEM
------------------------------------------------------------------------

The background has 4 layers, always in this order (bottom to top):

Layer 1 — Base:
  Solid background base color (#FAF8F4)
  No texture, no gradient here.

Layer 2 — Grain:
  Very fine SVG noise texture, opacity 0.035
  Gives the paper feel without looking designed.

Layer 3 — Atmospheric:
  One or two radial gradient blobs, very large (600–900px radius)
  Opacity 0.06–0.10 maximum. If you can clearly see it, it's too strong.
  Color: emerald tinted (hsl(155, 40%, 92%)) for the primary, 
         warm neutral (hsl(40, 30%, 90%)) for secondary if needed
  Position: varies per page (defined per page below)
  These are completely static — no animation, no movement.

Layer 4 — Structural (docs/dashboard only):
  Extremely faint grid or contour lines, opacity 0.025
  For docs: suggests graph paper / technical drafting
  For dashboard: suggests a data grid / operational surface
  Never visible as a design element. Only felt.

Pages where Layer 3 is active:
  Landing — behind hero (top-left), behind final CTA (bottom-right)
  Auth — centered, very subtle
  Docs home — faint, top area only
  Quickstart — top-left, follows the step flow
  Dashboard — present but minimal

Pages where Layer 3 is minimal or absent:
  Tool reference pages — replaced by subtle tool-specific line patterns
  API reference — no atmospheric glow at all
  Settings — none, pure paper only

STEP FLOW
------------------------------------------------------------------------

Steps are numbered 1–5. Each step has:
  - Step number and title (visible even when collapsed)
  - Status: pending (text muted) / active (text primary) / complete (accent text)
  - Content reveals on active step only (progressive disclosure)
  - Complete steps show a small checkmark, content collapses

Step 1 — Create your account
  Content:
    "If you haven't already, sign in with Google."
    Single link/button: "Sign in → /auth"
    If already signed in: show "You're signed in as [email]. Continue." with checkmark.

Step 2 — Get your API key
  Content:
    "Go to your dashboard and create an agent key."
    Link: "Open dashboard →"
    A note on key format: "Your key looks like: opctx_xxxxxxxxxxxxxxxx"
    — Small code block, JetBrains Mono

Step 3 — Copy your MCP config
  Content:
    This is the most important step. Spend the most space here.
    
    Show a config block per client tab. Real, working configs.

    Claude Code tab:
      {
        "mcpServers": {
          "opticontext": {
            "type": "http",
            "url": "https://mcp.opticontext.dev/mcp",
            "headers": {
              "Authorization": "Bearer YOUR_AGENT_KEY"
            }
          }
        }
      }

    Cursor tab:
      Show Cursor's MCP config format (cursor/.cursorrules or settings.json path)
      Same endpoint and auth header structure

    OpenClaw tab:
      Show agent config format appropriate to OpenClaw's integration

    Custom MCP Client tab:
      Show the raw HTTP request structure:
      POST https://mcp.opticontext.dev/mcp
      Authorization: Bearer YOUR_AGENT_KEY
      Content-Type: application/json

    Each block has a prominent copy button.
    Below each block: "Replace YOUR_AGENT_KEY with the key from step 2."

Step 4 — Make your first call
  Content:
    Show a simple tool invocation — IntelliSearch is the best first call.
    
    Example prompt to the agent:
      "Search for the latest developments in MCP servers"
    
    What the agent sends to OptiContext internally:
      {
        "jsonrpc": "2.0",
        "method": "tools/call",
        "params": {
          "name": "opticontext_search",
          "arguments": {
            "query": "latest developments in MCP servers",
            "mode": "quick"
          }
        },
        "id": 1
      }
    
    Copy button on this block as well.
    Note: "You don't need to write this JSON yourself. Your agent does it automatically."

Step 5 — Verify the response
  Content:
    Show a sample truncated response structure:
      {
        "jsonrpc": "2.0",
        "result": {
          "content": [
            {
              "type": "text",
              "text": "..."
            }
          ]
        },
        "id": 1
      }
    
    Below: "If you see this structure, your integration is working."
    
    Green success chip: "Integration verified"
    
    Two next steps:
      "Explore all four tools →" links to /docs/tools/intellisearch
      "View full API reference →" links to /docs/api-reference

SECTIONS
------------------------------------------------------------------------

Authentication:
  Heading: Zodiak 2xl
  Content:
    Key format: opctx_<hex>
    Header: Authorization: Bearer <key>
    Key creation: via dashboard only
    Token type: long-lived agent keys (not JWTs at the endpoint level)

  Code block:
    curl -X POST https://mcp.opticontext.dev/mcp \
      -H "Authorization: Bearer opctx_your_key_here" \
      -H "Content-Type: application/json" \
      -d '{ ... }'

Endpoints:

  POST /mcp
    Primary MCP endpoint. Accepts all tool calls.
    Transport: Streamable HTTP
    Format: JSON-RPC 2.0
    Sessions: optional Mcp-Session-Id header for stateful sessions

  POST /upload
    File upload endpoint for DeepDoc.
    Content-Type: multipart/form-data
    Max file size: 50MB
    Returns: file_id used in opticontext_analyze calls

  GET /health
    Health check. Returns 200 if operational.
    No auth required.

  GET /usage
    Returns current usage stats for the authenticated key.
    Auth required.

Tool Schemas:
  Show the JSON schema for each MCP tool.
  One section per tool. Code block per schema.

  opticontext_search (IntelliSearch)
  opticontext_tts (VoiceBridge)
  opticontext_analyze (DeepDoc)
  opticontext_memory_write (MemoryCore)
  opticontext_memory_search (MemoryCore)

Error Codes:
  Table: Code · HTTP Status · Meaning · Resolution

  INVALID_KEY       401   API key missing or malformed
  KEY_NOT_FOUND     401   API key does not exist
  KEY_REVOKED       401   API key has been revoked
  RATE_LIMITED      429   Per-agent rate limit exceeded
  TOOL_UNAVAILABLE  503   Downstream provider temporarily unavailable
  CONTEXT_TOO_LARGE 413   Input exceeds model context window
  UPLOAD_TOO_LARGE  413   File exceeds 50MB limit
  UNSUPPORTED_TYPE  415   File type not supported by DeepDoc

Rate Limits:
  Per-key per-day limits for each tool.
  Budget guard behavior: automatic fallback before hard limit.
  Table: Tool · Daily limit · Behavior at limit

Transport:
  Short section on Streamable HTTP behavior.
  MCP-Session-Id header for session persistence.
  Streaming response behavior for VoiceBridge.
